# 2048 게임 계획 작업 지침

## 배경
이 프로젝트(`my-blog`)는 마크다운 기반 블로그 + 미니 웹앱 포트폴리오다. 사용자가 새 웹앱을 요청하면 Plan → Build → Review → Embed 순서로 진행하며, 지금은 Plan 단계다. 프로젝트 루트의 `CLAUDE.md`를 참고해도 좋다.

## 요청받은 웹앱
2048 게임: 방향키(모바일에서는 스와이프 제스처)로 숫자 타일을 밀어서 같은 숫자끼리 합치는 퍼즐 게임. 점수판 포함.

## 해야 할 일
1. `C:\Users\SNOO\Desktop\my-blog\apps\2048\spec.md` 파일에 구현 계획을 작성한다. 다음 내용을 반드시 포함할 것:
   - **게임 규칙 요약**: 4x4 그리드, 방향키로 모든 타일을 한 방향으로 밀고 같은 숫자끼리 병합, 병합될 때마다 병합된 값만큼 점수 증가, 이동이 실제로 일어났을 때만 빈 칸 중 하나에 랜덤으로 2(90%) 또는 4(10%) 타일 생성, 2048 타일이 나오면 승리, 더 이상 이동/병합이 불가능하면 패배, 재시작 버튼 필요.
   - **파일 구조**: `/apps/2048/` 폴더 안에 어떤 파일을 만들지 (예: index.html, style.css, game.js로 분리할지, 혹은 단일 파일로 할지) — 근거와 함께 결정할 것.
   - **핵심 로직 설계**: 4방향 이동/병합을 어떻게 하나의 로직으로 통일해서 구현할지(예: 방향에 따라 배열을 회전/전치해서 "왼쪽으로 밀기" 로직 하나만 구현하는 방식 등), 한 번의 병합에서 같은 타일이 연쇄로 다시 병합되지 않도록 막는 방법, 점수판 갱신 방식, 랜덤 타일 생성 방식, 승리/패배 판정 방법.
   - **입력 처리**: 키보드 방향키(및 WASD 등 대체 키 여부는 자유 결정) + 모바일 터치 스와이프 제스처 둘 다 지원하는 방법.
   - **스타일**: 숫자 크기별 타일 색상 구분, 반응형 레이아웃(모바일 화면에서도 그리드가 잘리지 않고 꽉 차게 보이도록), 점수판 위치와 디자인.
   - **외부 의존성**: 라이브러리는 최소화한다. 이 게임은 순수 JS로 충분히 구현 가능하므로 라이브러리 없이 설계할 것을 강력히 권장한다(불가피한 경우에만 CDN 사용 근거를 명시).
2. 계획만 작성하고 실제 게임 코드는 작성하지 않는다. 구현(Build)은 이후 별도의 서브에이전트가 담당한다.

## 제약
- `spec.md` 한 파일만 만든다. 그 외 어떤 파일도 만들거나 수정하지 않는다.
- 프로젝트의 다른 파일(`build.js`, `lib/`, `public/`, `posts/`, `index.html` 등)은 절대 건드리지 않는다.

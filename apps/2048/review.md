# 2048 게임 검증(Review) 결과

검증일: 2026-09-07
검증 방법: `spec.md`와 `index.html`/`style.css`/`game.js` 코드 리딩 + Claude Browser로 임시 정적 서버(포트 5199, 기존 5173 서버는 건드리지 않음)를 띄워 실제 브라우저(Chromium 기반)에서 조작하며 확인. 데스크톱 뷰포트와 모바일(375px) 뷰포트 모두 테스트.

## 종합 결론
핵심 게임 로직(4방향 이동 통합, 병합, 재병합 방지, 점수/최고점수, 재시작, 반응형 레이아웃)은 spec.md 설계를 정확히 따르고 있으며 실제 브라우저에서도 정상 동작함을 확인했습니다. 코드 리딩 중 **승리와 동시에 패배 조건이 발생하는 극단적인 엣지 케이스에서 게임이 멈춰버리는(dead-end) 버그 1건**을 발견하여 직접 수정했습니다.

## 발견한 문제 및 수정 내역

### 문제: 승리와 패배가 같은 이동에서 동시에 발생하면 게임이 멈춤 (dead-end)

**위치**: `game.js`의 `handleMove` 함수

**증상**:
```js
if (!hasWon && hasTileValue(board, 2048)) {
  hasWon = true;
  showOverlay("You Win!", true);
  return;   // <- 여기서 즉시 return
}

if (isGameOver(board)) {
  gameOver = true;
  showOverlay("Game Over!", false);
}
```
어떤 이동이 (a) 처음으로 2048 타일을 만들면서 (b) 동시에 보드를 완전히 채우고 더 이상 어떤 방향으로도 이동/병합이 불가능한 상태를 만드는 경우, 위 코드는 "You Win!" 오버레이를 띄운 뒤 `return`하기 때문에 `isGameOver` 검사가 전혀 실행되지 않습니다.

이후 사용자가 "계속하기"를 누르면 오버레이는 사라지지만 보드는 이미 멈춘 상태이므로, 어떤 방향키를 눌러도 `computeMove(...).moved`가 항상 `false`가 되어 `handleMove`가 아무 반응 없이 조용히 종료됩니다. 즉 "Game Over!" 메시지가 영원히 뜨지 않고, 사용자 입장에서는 게임이 그냥 멈춰버린 것처럼 보이는 dead-end 상태가 됩니다.

spec.md 3.4절은 "승리 조건 검사 후 알림 표시"와 "패배 조건 검사 후 알림 표시"를 별개의 순차 단계로 명시하고 있어, 승리 시 조기 `return`으로 패배 검사를 건너뛰는 것은 설계 의도에서 벗어난 누락입니다.

**수정**: `return`을 제거하여 승리 조건 처리 후에도 항상 `isGameOver` 검사가 실행되도록 변경했습니다. 두 조건이 동시에 만족되는 경우 최종적으로 "Game Over!" 오버레이가 표시되며(마지막에 실행되는 검사이므로), 최소한 게임이 조용히 멈추는 대신 항상 명확한 최종 상태 메시지를 사용자에게 보여주게 됩니다.

```js
if (!hasWon && hasTileValue(board, 2048)) {
  hasWon = true;
  showOverlay("You Win!", true);
}

// Always check game-over too, even on the same move that first wins ...
if (isGameOver(board)) {
  gameOver = true;
  showOverlay("Game Over!", false);
}
```

**수정 후 검증**: 파일 저장 후 브라우저를 새로고침해 콘솔 에러 없이 정상 로드되는지, 기존 핵심 동작(이동/병합/재시작/WASD)이 그대로 동작하는지 재확인했습니다(모두 정상). 이 특정 엣지 케이스(승리와 동시 패배)는 확률적으로 매우 드물게 발생하는 상황이라 실제 플레이로 재현하지는 않았고, 코드 흐름 분석으로 수정이 올바름을 확인했습니다.

## 그 외 참고 사항 (버그는 아님)
- `render()`가 매 이동마다 `tile-layer`를 완전히 비우고 모든 타일 DOM을 새로 생성하는 방식이라, 기존에 있던 타일도 매번 `tile-appear`(scale-in) 애니메이션이 다시 재생됩니다. spec.md 5.1의 "타일 등장/이동 시 살짝 커지는 효과 등"이라는 표현이 슬라이딩 이동 애니메이션을 엄격히 요구하는 것은 아니라고 판단해 버그로 취급하지 않았으나, 참고로 남깁니다.

# 2048 게임 구현 계획 (spec.md)

## 1. 게임 규칙 요약
- 보드: 4x4 그리드 (16칸), 각 칸은 비어 있거나 2의 거듭제곱 숫자 타일(2, 4, 8, ...)을 가진다.
- 시작 상태: 빈 보드에서 랜덤한 두 칸에 각각 2(90% 확률) 또는 4(10% 확률) 타일을 생성한다.
- 조작: 방향키(↑↓←→)를 누르면 보드 위의 모든 타일이 해당 방향 끝까지 밀린다.
  - 같은 방향으로 밀리는 도중 같은 숫자의 타일이 인접하면 하나로 합쳐지고, 값은 두 배가 된다.
  - 한 번의 이동에서 이미 합쳐진 타일은 같은 이동 내에서 다시 합쳐지지 않는다 (예: 2,2,4 → 좌로 밀면 4,4가 되고 그 둘은 같은 턴에 다시 합쳐져 8이 되지 않는다. 결과는 [4,4]).
- 점수: 두 타일이 합쳐질 때마다 합쳐진 결과값(예: 2+2→4면 4점)만큼 점수에 누적한다. 한 번의 이동에서 여러 쌍이 합쳐지면 모두 합산한다.
- 새 타일 생성: 이동으로 인해 보드 상태가 실제로 변한 경우에만(즉, 어떤 타일이라도 위치나 값이 바뀐 경우), 이동 처리가 끝난 뒤 빈 칸 중 하나를 무작위로 골라 2(90%) 또는 4(10%) 타일을 생성한다. 아무 타일도 움직이거나 합쳐지지 않았다면(보드에 변화 없음) 새 타일을 생성하지 않는다.
- 승리 조건: 보드에 2048 타일이 하나라도 생성되면 승리 메시지를 표시한다. (승리 후에도 "계속하기"를 눌러 게임을 이어갈 수 있게 하며, 더 큰 타일을 계속 만들 수 있다.)
- 패배 조건: 보드가 가득 찬 상태(빈 칸 없음)에서 4방향 중 어느 쪽으로 밀어도 이동이나 병합이 전혀 일어나지 않으면 패배(게임 오버) 메시지를 표시한다.
- 재시작: 언제든 누를 수 있는 "재시작(Restart)" 버튼을 제공하며, 누르면 점수를 0으로 초기화하고 보드를 비운 뒤 새 타일 2개를 생성해 처음부터 다시 시작한다.

## 2. 파일 구조
`/apps/2048/` 폴더 안에 다음 3개 파일로 분리한다.

- `index.html` — 마크업 구조(보드, 점수판, 재시작 버튼, 승리/패배 오버레이)와 CSS/JS 파일 링크만 포함.
- `style.css` — 레이아웃, 타일 색상, 반응형 스타일, 애니메이션(타일 등장/이동 시 살짝 커지는 효과 등)을 전담.
- `game.js` — 게임 상태(보드 배열, 점수), 입력 처리(키보드/터치), 이동/병합 로직, 렌더링, 승패 판정을 전담.

**근거**: CLAUDE.md 규칙상 웹앱은 `/apps/{앱이름}/` 폴더 안에서 자체 완결되어야 하며 외부 라이브러리는 최소화해야 한다. 단일 HTML 파일에 모든 것을 우겨넣을 수도 있지만, 2048은 렌더링 로직(CSS)과 게임 로직(JS)이 명확히 분리 가능하고 각각 100줄 이상이 될 것으로 예상되어(보드 렌더링, 4방향 이동 로직, 스와이프 처리, 승패 판정, 애니메이션 등), 3파일 분리가 Build 단계에서의 가독성과 이후 Review 단계에서의 디버깅을 더 쉽게 만든다. 파일 수가 적어(3개) 폴더 자체 완결성은 그대로 유지된다.

## 3. 핵심 로직 설계

### 3.1 보드 표현
- 4x4 2차원 배열(`board[row][col]`)로 상태를 표현한다. 값은 0(빈 칸) 또는 2의 거듭제곱 숫자.

### 3.2 4방향 이동을 하나의 로직으로 통일
방향마다 별도 로직을 짜지 않고, **"왼쪽으로 밀기" 로직 하나만 구현**한 뒤 방향에 따라 보드를 회전시켜 재사용한다.

- 핵심 함수 `slideRowLeft(row)`: 한 행(1차원 배열, 길이 4)을 입력받아
  1. 0을 제외한 값들만 순서대로 추출 (compact)
  2. 왼쪽부터 인접한 두 값이 같으면 병합(값 2배, 점수 누적), 병합된 타일은 "이번 턴에 병합됨" 표시를 남겨 같은 턴에 재병합되지 않도록 함
  3. 병합 후 다시 0을 채워 길이 4로 맞춤 (compact)
  4. 원래 행과 비교해 변화가 있었는지(moved) 여부도 함께 반환
- 방향별 처리:
  - **왼쪽**: 각 행에 `slideRowLeft` 그대로 적용.
  - **오른쪽**: 각 행을 반전(reverse)한 뒤 `slideRowLeft` 적용, 결과를 다시 반전.
  - **위쪽**: 보드를 전치(transpose, 행↔열 교환)한 뒤 각 행에 `slideRowLeft` 적용, 결과를 다시 전치.
  - **아래쪽**: 보드를 전치한 뒤 각 행을 반전, `slideRowLeft` 적용, 다시 반전 후 다시 전치.
- 이렇게 하면 회전/전치 유틸 함수(`transpose`, `reverseRow`)와 `slideRowLeft` 하나만으로 4방향을 모두 처리할 수 있다.

### 3.3 같은 턴 재병합 방지
- `slideRowLeft` 내부에서 compact된 배열을 왼쪽부터 순회하면서 "직전에 병합으로 생성된 타일"인지 표시하는 방법 대신, 더 간단하게: compact된 배열을 순회하며 인접한 두 값이 같고 **또한 방금 병합해서 만든 값이 아닐 때만** 병합하도록, 병합 후 인덱스를 두 칸 건너뛰는 방식을 사용한다. 즉 `i`번째와 `i+1`번째가 같으면 병합해서 결과 배열에 넣고 `i`를 2 증가시키며, 병합된 결과 타일은 다시 비교 대상으로 삼지 않는다. 이렇게 인덱스를 건너뛰는 방식만으로 연쇄 재병합이 자연히 방지되므로 별도의 플래그 배열 없이 구현 가능하다.

### 3.4 이동 처리 흐름
1. 현재 보드를 깊은 복사(deep copy)해 둔다.
2. 방향에 맞춰 3.2의 방식으로 새 보드를 계산하고, 병합으로 발생한 점수 합을 구한다.
3. 새 보드와 원래 보드를 비교(JSON.stringify 비교 또는 각 셀 비교)해 실제로 변화가 있었는지(moved) 판단한다.
4. `moved`가 true이면:
   - 점수판에 이번 이동에서 발생한 점수를 더한다.
   - 빈 칸 목록을 구해 무작위로 하나를 골라 2(90%) 또는 4(10%) 타일을 생성한다.
   - 화면을 다시 렌더링한다.
   - 승리 조건(2048 타일 존재, 아직 승리 알림을 안 띄웠다면) 검사 후 알림 표시.
   - 패배 조건(빈 칸이 없고 4방향 모두 moved=false로 시뮬레이션됨) 검사 후 알림 표시.
5. `moved`가 false이면 아무것도 하지 않는다(렌더링도, 타일 생성도 생략).

### 3.5 점수판 갱신
- 전역 변수 `score`를 두고, 병합이 일어날 때마다 병합 결과값을 더한다.
- 이동 처리가 끝난 뒤 `score`를 화면의 점수 표시 요소(`textContent`)에 반영한다.
- 최고 점수(`best score`)는 `localStorage`에 저장해, 현재 점수가 최고 점수를 넘으면 갱신하고 페이지를 다시 열어도 유지되게 한다.

### 3.6 랜덤 타일 생성 방식
- 보드를 순회해 값이 0인 칸의 좌표 목록을 만든다.
- 목록이 비어 있지 않으면 `Math.random()`으로 인덱스 하나를 골라 해당 좌표에 값을 넣는다.
- 값은 `Math.random() < 0.9 ? 2 : 4`로 결정한다.

### 3.7 승리/패배 판정
- **승리**: 보드 전체를 순회해 값이 2048 이상인 칸이 있는지 확인. 처음 승리 조건을 만족한 순간에만 "승리" 오버레이를 띄우고, 이후에는 사용자가 "계속하기"를 누르면 다시 뜨지 않도록 `hasWon` 플래그로 관리.
- **패배**: 다음 두 조건을 모두 만족하면 패배로 판정.
  1. 빈 칸이 하나도 없음.
  2. 4방향(상하좌우) 각각에 대해 3.2의 이동 계산을 시뮬레이션했을 때 모두 `moved === false`(즉 어느 방향으로도 이동/병합이 불가능).
  - 이 판정은 매 이동이 성공적으로 끝난 직후에만 수행한다(불필요한 연산 방지).

## 4. 입력 처리

### 4.1 키보드
- `document`에 `keydown` 이벤트 리스너를 등록한다.
- `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight` 키를 방향에 매핑한다. 추가로 `W`/`A`/`S`/`D`(대소문자 무관)도 동일하게 매핑해 대체 입력을 지원한다.
- 방향키 입력 시 페이지 스크롤이 함께 일어나는 것을 막기 위해 해당 키에 대해 `event.preventDefault()`를 호출한다.

### 4.2 모바일 터치 스와이프
- 게임 보드 요소에 `touchstart`, `touchend` 이벤트 리스너를 등록한다(터치 중간 이동을 추적할 필요 없이 시작점과 끝점만 비교하면 충분).
- `touchstart`에서 시작 좌표(`startX`, `startY`)를 기록.
- `touchend`에서 끝 좌표와 시작 좌표의 차이(`dx`, `dy`)를 계산.
- 최소 스와이프 거리(예: 20px) 이상일 때만 스와이프로 인정해 오탐(탭)을 방지한다.
- `abs(dx) > abs(dy)`이면 좌우 스와이프로 판단(`dx > 0`이면 오른쪽, `dx < 0`이면 왼쪽), 아니면 상하 스와이프로 판단(`dy > 0`이면 아래, `dy < 0`이면 위).
- 판단된 방향으로 3.4의 이동 처리 함수를 동일하게 호출한다(키보드와 로직 공유).
- 스와이프 시 페이지 자체가 스크롤/바운스되지 않도록 보드 영역에 `touch-action: none` CSS를 적용하고, 필요 시 `touchmove`에서 `preventDefault()`를 호출한다.

## 5. 스타일 설계

### 5.1 타일 색상
- 숫자 값에 따라 배경색을 다르게 매핑한다(원작 2048과 유사한 팔레트를 참고하되 직접 정의):
  - 2: 연한 베이지, 4: 약간 진한 베이지, 8: 주황, 16: 진한 주황, 32: 빨강 계열, 64: 진한 빨강, 128~512: 노랑 계열(글자 크기 살짝 축소), 1024~2048: 금색/밝은 노랑(글자 크기 더 축소), 2048 초과: 어두운 배경에 밝은 글자.
- 값이 커질수록(자릿수가 늘어날수록) 타일 안 폰트 크기를 CSS 클래스(`.tile-2`, `.tile-4`, ... 또는 자릿수 기반 클래스)로 단계적으로 줄여 4칸 안에서 잘리지 않게 한다.
- 매핑 값이 없는(팔레트에 정의 안 된 매우 큰 수) 경우를 대비해 기본(fallback) 스타일도 하나 정의한다.

### 5.2 반응형 레이아웃
- 게임 보드 컨테이너의 크기를 고정 px 대신 `min(90vw, 90vh, 500px)` 형태로 지정해 화면 크기에 맞춰 정사각형을 유지하면서 최대 크기를 제한한다.
- 그리드는 CSS Grid(`display: grid; grid-template-columns: repeat(4, 1fr); grid-template-rows: repeat(4, 1fr);`)로 구성해 셀 크기가 컨테이너 크기에 비례해 자동으로 조정되게 한다.
- 타일 간 간격(gap)도 상대 단위(`vw` 또는 컨테이너 대비 %) 혹은 작은 고정값으로 지정해 작은 화면에서도 비율이 깨지지 않게 한다.
- `viewport` 메타 태그(`width=device-width, initial-scale=1`)를 설정하고, `body`에 `overflow-x: hidden`을 적용해 좌우 스크롤이 생기지 않게 한다.
- 점수판/버튼 등 상단 UI도 flexbox로 구성해 좁은 화면에서 줄바꿈되거나 자연스럽게 축소되도록 한다.

### 5.3 점수판 및 버튼 배치
- 보드 위쪽에 헤더 영역을 두고, flexbox로 좌측에 타이틀("2048"), 우측에 점수판 2개(현재 점수 SCORE, 최고 점수 BEST)를 박스 형태로 배치한다.
- 헤더 아래(또는 옆)에 "재시작(New Game)" 버튼을 배치. 버튼은 언제든 클릭 가능해야 하며, 클릭 시 2.의 재시작 로직을 호출한다.
- 승리/패배 시에는 보드 위에 반투명 오버레이를 씌워 "You Win!" / "Game Over!" 메시지와 재시작(또는 승리 시 "계속하기") 버튼을 표시한다.
- 다크/라이트 모드는 별도로 만들지 않고 원작 2048 느낌의 밝은 베이지 배경 하나로 통일한다(범위를 벗어나는 추가 기능은 배제).

## 6. 외부 의존성
- **없음.** 이 게임은 순수 HTML/CSS/JavaScript(바닐라 JS)만으로 완전히 구현 가능하다.
  - 애니메이션: CSS `transition`만으로 타일 등장/이동 효과 처리 가능.
  - 랜덤: `Math.random()`으로 충분.
  - 상태 저장(최고 점수): 브라우저 내장 `localStorage` API 사용.
  - 터치 제스처: 표준 `TouchEvent`(`touchstart`/`touchend`)로 충분히 구현 가능, 별도 제스처 라이브러리 불필요.
- CLAUDE.md 규칙(외부 라이브러리 최소화)에 따라 CDN도 사용하지 않는다.

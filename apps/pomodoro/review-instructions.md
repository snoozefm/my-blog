# 뽀모도로 타이머 검증(Review) 작업 지침

## 배경
`my-blog` 프로젝트의 Plan → Build → Review → Embed 사이클 중 지금은 **Review** 단계다. 계획은 `C:\Users\SNOO\Desktop\my-blog\apps\pomodoro\spec.md`, 구현은 `C:\Users\SNOO\Desktop\my-blog\apps\pomodoro\index.html`, `style.css`, `timer.js`에 있다 (Build 서브에이전트가 작성함). 너는 Build를 작성한 서브에이전트와 별개의 독립적인 검토자다.

## 해야 할 일
1. `spec.md`를 읽고, 구현된 3개 파일(`index.html`, `style.css`, `timer.js`)의 코드를 직접 읽어라.
2. Claude Browser 도구로 실제 브라우저에서 앱을 실행하고 다음을 확인해라.
   - 초기 로드 시 25:00(work 슬라이더 기본값)이 표시되고, work 배경 스타일인지.
   - 시작 버튼을 누르면 카운트다운이 실제로 줄어드는지(몇 초 기다려서 숫자가 감소하는지 확인).
   - 일시정지 후 다시 시작하면 멈췄던 지점부터 이어지는지(시간이 튀거나 초기화되지 않는지).
   - 리셋을 누르면 현재 세션 타입 기준으로 슬라이더 값으로 되돌아가는지.
   - **슬라이더 반영 규칙이 spec대로 동작하는지**: idle 상태에서 work 슬라이더를 움직이면 화면 숫자가 즉시 바뀌는지. 시작(running) 후에 슬라이더를 움직이면 화면 숫자는 안 바뀌는지(다음 세션에만 반영되어야 함).
   - **세션 자동 전환**: 실제로 몇 분을 기다리기 어렵다면, work 슬라이더를 최소값(5분)으로 줄이는 것만으로는 여전히 5분이 걸리므로, 코드를 직접 콘솔에서 조작해(예: `timer.js`의 내부 상태를 직접 바꾸지 말고, 페이지의 전역에 노출된 값이 없다면 `Date.now`를 일시적으로 monkeypatch 하거나, 혹은 남은 시간이 얼마 안 남은 것처럼 만들기 위해 개발자 콘솔에서 브라우저의 시간 흐름을 빠르게 시뮬레이션하는 방법을 스스로 판단해) 세션 종료 시점을 실제로 재현해서, work→break 자동 전환과 자동 시작, 세션 카운터 증가, 배경색/라벨/타이틀 변경, 비프음 재생(에러 없이 호출되는지)이 실제로 일어나는지 확인해라. 이 과정이 너무 번거롭다면 최소한 코드 리딩으로 로직이 spec과 일치하는지 철저히 검증하고, 왜 실제 재현을 안 했는지/했는지 review.md에 명시해라.
   - 모바일 폭(375px)으로 리사이즈했을 때 레이아웃이 깨지거나 가로 스크롤이 생기지 않는지, 슬라이더와 버튼이 터치하기 적당한 크기인지.
   - 브라우저 콘솔에 에러가 없는지.
3. 코드 자체도 검토해라: spec.md의 타임스탬프 기반 카운트다운 설계(탭이 백그라운드로 가도 정확해야 함), 상태 전환 로직, 슬라이더 반영 규칙이 실제로 그렇게 구현되어 있는지 로직을 추적해서 확인해라.
4. 검증 결과를 `C:\Users\SNOO\Desktop\my-blog\apps\pomodoro\review.md`에 정리해서 작성해라. 발견한 문제(있다면)와 각 항목의 통과/실패 여부를 명시할 것.
5. **문제를 발견했다면 직접 수정해라** (`index.html`/`style.css`/`timer.js` 범위 내에서). 수정 후 다시 브라우저에서 확인해서 고쳐졌는지 검증하고, `review.md`에 어떤 문제를 어떻게 고쳤는지도 기록해라.

## 제약
- `/apps/pomodoro/` 폴더 안의 `index.html`, `style.css`, `timer.js`, 그리고 새로 작성할 `review.md`만 수정/생성한다.
- 프로젝트의 다른 파일(`build.js`, `lib/`, `public/`, `posts/`, `apps/2048/`, 루트 `index.html`, `spec.md`, 지침 파일들)은 건드리지 않는다.
- 프리뷰 서버(포트 5173)는 이미 실행 중일 수 있으니, 새 서버를 띄워야 한다면 반드시 다른 포트를 쓰거나 기존 서버를 건드리지 말 것. 절대 `taskkill`처럼 다른 프로세스까지 죽일 수 있는 광범위한 명령을 쓰지 말 것 — 반드시 이 세션에서 직접 띄운 서버만, 정상적인 방법(예: 해당 서버의 serverId로 preview_stop)으로 종료할 것.

## 완료 후
`review.md`의 핵심 내용(통과 항목, 발견/수정한 문제)을 요약해서 보고할 것.

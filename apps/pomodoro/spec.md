# 뽀모도로 타이머 구현 계획 (spec.md)

## 1. 기능 요약
- **카운트다운 타이머**: 화면 중앙에 남은 시간을 `MM:SS` 형식(예: `25:00`)의 큰 숫자로 표시한다.
- **컨트롤 버튼**: 시작(Start) / 일시정지(Pause) / 리셋(Reset) 3개 버튼을 둔다.
  - 시작 버튼은 타이머가 정지 또는 일시정지 상태일 때 보이고, 실행 중에는 "일시정지" 버튼으로 토글된다(즉, 시작/일시정지는 하나의 버튼이 상태에 따라 라벨과 동작을 바꾸는 방식).
  - 리셋 버튼은 항상 눌러 사용 가능하며, 누르면 진행 중인 세션을 멈추고 현재 세션 타입(work/break)의 슬라이더 설정값으로 남은 시간을 되돌린다(전체 사이클을 처음 work 세션으로 되돌리지는 않고, 현재 세션 종류를 유지한 채 그 세션의 시간만 리셋한다).
- **세션 전환 방식**: work 세션과 break 세션이 번갈아 진행된다.
  - 순서: work → break → work → break … 무한 반복.
  - 한 세션이 0:00에 도달하면 **자동으로 다음 세션으로 전환되고 자동으로 시작**한다(사용자가 다시 시작 버튼을 누를 필요 없음). 이렇게 하는 이유는 뽀모도로 기법의 핵심이 "타이머를 계속 신경 쓰지 않고 알림만 듣고 전환하는 것"이기 때문이다. 단, 자동 시작이 부담스러울 수 있으므로 세션 전환 시 3번 항목의 알림을 명확히 주고, 화면 배경색 전환으로 지금 무슨 세션인지 항상 한눈에 알 수 있게 한다.
  - 세션 전환 시 알림 방식: **① 소리(Web Audio API로 생성한 짧은 비프음) + ② 화면 표시(배경색 전환 + 세션 라벨 텍스트 변경, 예: "집중 시간" ↔ "쉬는 시간") + ③ 문서 타이틀(`<title>`) 변경**의 3가지를 함께 사용한다.
    - 브라우저 알림(Notification API)은 사용하지 않는다. 권한 요청 UX가 번거롭고, 탭이 열려 있는 상태를 전제로 하는 미니 웹앱 특성상 화면 표시 + 소리만으로 충분하기 때문이다(과도한 기능 확장 방지, CLAUDE.md의 라이브러리/기능 최소화 원칙과 일관).
    - 비프음은 외부 오디오 파일 없이 `AudioContext`로 오실레이터(oscillator)를 짧게(예: 0.2초, 800Hz) 울려 구현한다. 이렇게 하면 별도 파일이나 CDN 없이 순수 JS로 소리를 낼 수 있다.
  - **현재 세션 카운트 표시**: 화면에 "N번째 뽀모도로" 또는 "세션 3" 같은 형태로 지금까지 완료한 work 세션 횟수를 표시한다. work 세션이 끝날 때마다(즉 work→break 전환 시) 카운터를 1 증가시킨다. 이 카운터는 리셋 버튼을 눌러도 유지하되(개별 세션 리셋은 시간만 초기화), 페이지를 새로고침하면 0으로 돌아간다(localStorage 등 영속 저장은 범위를 벗어나므로 사용하지 않는다).

## 2. 슬라이더 요구사항
- **집중(work) 시간 슬라이더**
  - 범위: 5분 ~ 60분 (`min="5" max="60"`)
  - 기본값: 25분 (전통적인 뽀모도로 기법 기준)
  - 단위: 1분 단위(`step="1"`)
- **쉬는(break) 시간 슬라이더**
  - 범위: 1분 ~ 30분 (`min="1" max="30"`)
  - 기본값: 5분
  - 단위: 1분 단위(`step="1"`)
- **실시간 숫자 표시**: 각 슬라이더 옆(또는 위)에 `<span>` 요소를 두어 현재 슬라이더 값을 "25분" 형태로 표시한다. 슬라이더의 `input` 이벤트(드래그 중 실시간 반영, `change`가 아닌 `input`을 사용해 드래그하는 동안에도 즉시 갱신되게 함)가 발생할 때마다 해당 span의 `textContent`를 갱신한다.
- **타이머 실행 중 슬라이더를 조정하면?**
  - 규칙: **슬라이더는 항상 "다음 세션부터" 반영된다. 즉, 타이머가 실행 중이거나 일시정지 상태여도 현재 진행 중인 세션의 남은 시간은 슬라이더 조작으로 즉시 바뀌지 않는다.** 슬라이더는 각 세션 타입(work/break)의 "기본 길이" 설정값을 바꾸는 역할만 하고, 그 값은 다음번에 해당 세션 타입이 시작될 때 적용된다.
  - 예외: **타이머가 정지 상태(아직 한 번도 시작 안 했거나, 리셋 직후)일 때는** 슬라이더 조정이 남은 시간 표시에 **즉시** 반영된다. 이렇게 하면 사용자가 시작 전에 원하는 시간을 미리 보면서 설정할 수 있다.
  - 판단 근거: 실행 중에 슬라이더를 만졌다고 남은 시간이 갑자기 늘거나 줄면(특히 이미 흐른 시간이 있는 상태에서) 사용자가 혼란스러울 수 있다("일시정지 중에는 즉시 반영, 실행 중에는 다음 세션부터"처럼 상태별로 다르게 하면 규칙이 복잡해지므로, "타이머가 한 번이라도 카운트다운을 시작했는지"를 기준으로 단순하게 나눈다). 즉 상태는 두 가지로만 구분한다:
    - **`idle`(정지/리셋 상태, 아직 카운트다운 시작 전)**: 슬라이더 조정 → 남은 시간 표시 즉시 갱신.
    - **`running` 또는 `paused`(한 번이라도 시작한 뒤)**: 슬라이더 조정 → 남은 시간 표시 불변, 슬라이더가 가리키는 값은 다음 세션 전환 시에만 적용.
  - 일시정지 상태에서 리셋을 누르면 `idle`로 돌아가므로, 그 뒤 슬라이더를 움직이면 다시 즉시 반영된다.
- **슬라이더 값 변경 시 남은 시간 표시 갱신 방법**: `idle` 상태에서는 슬라이더의 `input` 이벤트 핸들러 안에서 (a) 옆의 숫자 표시 갱신과 (b) 현재 세션 타입에 해당하는 슬라이더일 경우 남은 시간 표시(`MM:SS`)를 `해당 슬라이더 값 * 60`초로 재계산해 즉시 다시 그린다. 예를 들어 현재 세션이 work이고 idle 상태라면 work 슬라이더를 움직일 때만 타이머 표시가 갱신되고, break 슬라이더를 움직여도 (다음 break 세션에 반영될 뿐) 지금 보이는 숫자는 바뀌지 않는다.

## 3. 파일 구조
`/apps/pomodoro/` 폴더 안에 2048 앱과 동일한 패턴으로 3개 파일로 분리한다.

- `index.html` — 마크업 구조(타이머 표시, 세션 라벨, 시작/일시정지/리셋 버튼, work/break 슬라이더 2개와 값 표시, 세션 카운터)와 CSS/JS 파일 링크만 포함.
- `style.css` — 레이아웃, 큰 숫자 타이포그래피, work/break 배경색 전환, 슬라이더 커스텀 스타일, 반응형 스타일을 전담.
- `timer.js` — 타이머 상태(state: idle/running/paused, 세션 타입, 남은 시간), `setInterval` 기반 카운트다운 로직, 시작/일시정지/리셋 처리, 세션 전환 로직, 슬라이더 이벤트 처리, 알림(소리/타이틀/배경) 처리를 전담.

**근거**: CLAUDE.md 규칙상 웹앱은 `/apps/{앱이름}/` 폴더 안에서 자체 완결되어야 한다. 뽀모도로 타이머는 2048보다 로직 규모는 작지만(보드 연산이 없음), 상태 전환(idle/running/paused, work/break)과 슬라이더 상호작용, 타임스탬프 기반 정확한 카운트다운, 오디오 알림까지 합치면 JS가 100줄 내외로 예상되어 여전히 마크업/스타일/로직을 분리하는 편이 가독성이 좋다. `/apps/2048/`과 동일한 3파일 구조를 따라 프로젝트 전체의 일관성도 유지한다.

## 4. 핵심 로직 설계

### 4.1 상태 모델
- `sessionType`: `'work'` 또는 `'break'` (현재 어떤 세션인지)
- `timerState`: `'idle'`(시작 전/리셋 직후) / `'running'`(카운트다운 진행 중) / `'paused'`(일시정지)
- `sessionCount`: 완료한 work 세션 수 (초기값 0)
- `remainingMs`: 현재 세션에서 남은 시간(밀리초 단위로 내부 저장, 표시할 때만 초 단위로 변환)
- `targetTimestamp`: `running` 상태일 때, "이 타임스탬프(`Date.now()` 기준 절대 시각)에 카운트다운이 0이 된다"를 저장하는 값. 일시정지 시에는 그 시점까지 남은 시간을 `remainingMs`에 고정 저장하고 `targetTimestamp`는 버린다.

### 4.2 타임스탬프 기반 카운트다운 (탭 백그라운드 대응)
- `setInterval`을 250ms 주기로 돌리되(1초보다 짧게 잡아 화면 갱신이 매끄럽고, 브라우저가 백그라운드 탭에서 인터벌을 늦춰도 오차를 줄임), 매 tick마다 다음과 같이 계산한다:
  1. `now = Date.now()`
  2. `remaining = targetTimestamp - now` (밀리초)
  3. `remaining <= 0`이면 세션 종료 처리(4.4)로 분기.
  4. 그렇지 않으면 `remaining`을 `MM:SS`로 변환해 화면에 표시.
- 이렇게 **절대 목표 시각(`targetTimestamp`)과 현재 시각의 차이**로 남은 시간을 매번 재계산하기 때문에, `setInterval`이 백그라운드 탭에서 스로틀링되어 늦게 실행되더라도(예: 1초마다가 아니라 5초마다 실행되더라도) 실제 경과 시간은 정확하게 반영된다. `setInterval`의 콜백 호출 자체가 늦어질 수는 있지만, 콜백이 실행될 때 계산하는 `remaining` 값은 항상 정확하다.
- 시작(`start`) 시: `targetTimestamp = Date.now() + remainingMs` 로 설정하고 인터벌을 시작한다.
- 일시정지(`pause`) 시: 인터벌을 멈추고, `remainingMs = targetTimestamp - Date.now()`로 그 순간의 남은 시간을 고정 저장한다.
- 재시작(일시정지 → 시작) 시: 고정 저장해둔 `remainingMs`를 기준으로 다시 `targetTimestamp = Date.now() + remainingMs`를 계산해 이어서 진행한다.

### 4.3 시작 / 일시정지 / 리셋 상태 전환
- **시작 버튼 클릭**:
  - `idle` 상태였다면: `remainingMs`를 현재 `sessionType`에 해당하는 슬라이더 값(분)×60000으로 설정한 뒤 4.2의 시작 절차 수행, `timerState = 'running'`.
  - `paused` 상태였다면: 4.2의 "재시작" 절차만 수행, `timerState = 'running'`.
  - 버튼 라벨을 "일시정지"로 변경.
- **일시정지 버튼(시작 버튼이 토글된 상태) 클릭**: `timerState === 'running'`일 때만 동작. 4.2의 일시정지 절차 수행, `timerState = 'paused'`, 버튼 라벨을 "시작"으로 변경.
- **리셋 버튼 클릭**: 인터벌 정지, `timerState = 'idle'`, 현재 `sessionType`에 해당하는 슬라이더 값으로 `remainingMs` 재설정 후 화면 표시 갱신. 버튼 라벨을 "시작"으로 되돌림. (`sessionType`과 `sessionCount`는 그대로 유지 — 세션 종류/횟수까지 되돌리려면 페이지 새로고침을 이용하도록 안내.)

### 4.4 세션 전환 로직
- 카운트다운이 0 이하가 되면(4.2의 3번) 다음을 수행:
  1. 인터벌은 멈추지 않고 유지한다(자동으로 다음 세션이 이어서 시작되므로).
  2. 만약 방금 끝난 세션이 `work`였다면 `sessionCount += 1`.
  3. `sessionType`을 반대로 전환(`work` ↔ `break`).
  4. 알림 실행: 비프음 재생, 배경색 전환(CSS 클래스 토글), 세션 라벨 텍스트 변경, `document.title` 변경(예: "집중 시간 - 뽀모도로" ↔ "쉬는 시간 - 뽀모도로"), 세션 카운터 표시 갱신.
  5. 새 `sessionType`에 해당하는 슬라이더의 **현재 값**을 읽어 `remainingMs`를 설정(즉 이 시점이 "다음 세션부터 슬라이더 값 반영"이 실제로 일어나는 지점).
  6. `targetTimestamp = Date.now() + remainingMs`로 재설정해 자동으로 다음 세션 카운트다운을 이어간다(`timerState`는 `running` 유지).

### 4.5 슬라이더와 타이머 상태의 상호작용
- 두 슬라이더 각각에 `input` 이벤트 리스너를 등록한다.
- 핸들러 로직:
  1. 옆의 숫자 표시(`textContent`)를 항상 갱신(상태 무관하게 즉시 반영 — 이건 "슬라이더가 지금 몇 분을 가리키는지"를 보여주는 것뿐이므로 타이머 상태와 무관하게 항상 즉시 갱신되어야 함).
  2. `timerState === 'idle'` 이고, 이 슬라이더의 세션 타입이 현재 `sessionType`과 같을 때만: `remainingMs`를 새 슬라이더 값×60000으로 재계산하고 화면의 `MM:SS` 표시를 즉시 다시 그린다.
  3. 그 외 경우(실행 중/일시정지 중이거나, 지금 세션 타입과 다른 슬라이더를 조작한 경우)에는 표시를 바꾸지 않고 슬라이더의 값만 저장해 둔다(슬라이더 자체의 DOM 값이 곧 "다음에 적용할 설정값" 역할을 하므로 별도 변수 저장 없이 슬라이더 엘리먼트의 `.value`를 그때그때 읽어도 된다).

## 5. 스타일 설계
- **타이포그래피 중심 레이아웃**: 화면 중앙에 `MM:SS` 숫자를 매우 큰 폰트 크기(`clamp(4rem, 20vw, 10rem)` 등 뷰포트 비례+상한/하한)로 표시한다. 숫자는 고정폭처럼 보이도록 `font-variant-numeric: tabular-nums`를 적용해 초가 바뀔 때 자릿수 흔들림(레이아웃 시프트)이 없게 한다.
- **work/break 시각적 구분**: `<body>` 또는 최상위 컨테이너에 `.mode-work` / `.mode-break` 클래스를 토글해 배경색을 전환한다.
  - work: 차분한 톤(예: 짙은 남색/보라 계열 배경 + 밝은 텍스트) — "집중"을 상징.
  - break: 편안한 톤(예: 녹색/청록 계열 배경) — "휴식"을 상징.
  - `transition: background-color 0.6s ease`로 전환 시 부드럽게 색이 바뀌게 한다.
- **세션 라벨/카운터**: 타이머 숫자 위에 작은 텍스트로 "집중 시간" / "쉬는 시간"과 "N번째 뽀모도로"를 함께 표시.
- **버튼 UI**: 시작/일시정지 토글 버튼은 강조색(accent color)의 원형 또는 알약형 큰 버튼으로 눈에 띄게, 리셋 버튼은 보조 스타일(테두리만 있는 형태 등)로 구분한다. 버튼은 터치 타깃을 고려해 최소 44px 이상의 높이를 확보한다.
- **슬라이더 UI**: `input[type=range]`의 기본 스타일을 `-webkit-appearance: none` 등으로 초기화하고, 트랙과 thumb을 배경 테마에 맞는 커스텀 색상으로 스타일링한다. 각 슬라이더 위/옆에 라벨("집중 시간")과 실시간 값("25분")을 함께 배치한다.
- **반응형 레이아웃**: 전체를 `flexbox`(세로 방향, `align-items: center; justify-content: center`)로 중앙 정렬하고, 슬라이더 영역은 `max-width: 400px` 정도로 제한한 뒤 `width: 90%`로 좁은 화면에서도 여백을 확보한다. `viewport` 메타 태그(`width=device-width, initial-scale=1`)를 설정하고 `body { overflow-x: hidden }`으로 가로 스크롤을 방지한다. 버튼 그룹은 좁은 화면에서 세로로 쌓이거나(`flex-wrap: wrap`) 충분한 간격을 유지하도록 한다.

## 6. 외부 의존성
- **없음.** 순수 HTML/CSS/JavaScript(바닐라 JS)만으로 완전히 구현 가능하다.
  - 카운트다운: `setInterval` + `Date.now()` 타임스탬프 비교.
  - 알림음: 브라우저 내장 `AudioContext`(Web Audio API)로 오실레이터를 이용해 짧은 비프음 생성 — 외부 오디오 파일이나 라이브러리 불필요.
  - 슬라이더: 표준 `<input type="range">` 엘리먼트와 `input` 이벤트만으로 충분.
- CLAUDE.md 규칙(외부 라이브러리 최소화)에 따라 CDN도 사용하지 않는다.

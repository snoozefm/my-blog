클로드 코드와 함께 이 블로그를 만들면서, 프레임워크 없이도 **HTML, CSS, JavaScript**가 어떻게 역할을 나눠 맡는지 다시 정리해볼 수 있었습니다.

## HTML — 구조를 담당

HTML은 페이지의 뼈대를 만듭니다. 이 블로그에서는 `build.js`가 마크다운을 읽어 `<h1>`, `<p>`, `<pre><code>` 같은 HTML 태그로 변환합니다. 결국 브라우저가 실제로 읽는 것은 미리 만들어진 정적 HTML 파일이라, 로딩 속도가 빠르고 검색 엔진도 내용을 바로 읽을 수 있습니다.

## CSS — 디자인과 테마를 담당

CSS는 색상, 여백, 반응형 레이아웃을 책임집니다. 이번 프로젝트에서 가장 인상 깊었던 부분은 다음과 같습니다.

- `:root`에 정의한 CSS 변수(`--color-bg`, `--color-text` 등)로 라이트/다크 색상을 관리
- `data-theme` 속성과 `prefers-color-scheme` 미디어 쿼리를 함께 써서, 사용자가 수동으로 고른 테마가 시스템 설정보다 항상 우선하도록 처리
- `pre { overflow-x: auto; }`처럼 넓은 콘텐츠만 자체적으로 스크롤되게 해서 모바일 화면이 깨지지 않도록 함

## JavaScript — 동작과 상호작용을 담당

JavaScript는 두 가지 다른 자리에서 쓰였습니다.

1. **빌드 타임(Node.js)**: 마크다운을 HTML로 바꾸고, 코드 블록에 문법 강조를 입히고, 최종 HTML 파일을 생성하는 로직 전부
2. **런타임(브라우저)**: 다크 모드 토글 버튼을 클릭했을 때 `data-theme`를 바꾸고 `localStorage`에 저장하는 아주 작은 스크립트

같은 언어라도 어디서 실행되느냐에 따라 하는 일이 완전히 다르다는 걸 이번에 확실히 느꼈습니다.

## 정리

- HTML: 무엇을 보여줄지 (구조)
- CSS: 어떻게 보여줄지 (디자인)
- JavaScript: 사용자가 조작했을 때 무엇이 바뀔지 (동작)

세 가지 역할이 명확히 나뉘어 있다는 걸 이해하고 나니, 프레임워크 없이도 충분히 관리하기 쉬운 블로그를 만들 수 있었습니다.
